# NI-Script — 06: VM e determinismo

> FASE 11 · implementação: `engine/niscript/src/Vm.cpp`

## Modelo de execução

Stack machine sobre o bytecode plano (docs/05). Uma EXECUÇÃO = um
EVENTO em UMA instância (`NiVm::run(state, evento, params)`):

```
frame raiz (handler) → dispatch loop → {budget check → trace? → switch}
```

- SEM handler para o evento: nada acontece (retorno imediato —
  `up start` opcional, etc.);
- frames carregam: programa dono (emit cruza INSTÂNCIAS), a INSTÂNCIA
  dona (globais/self/links), base de pilha, regionBase e `fromEmit`
  (contagem da profundidade de emissão);
- regiões (repair/timeout) vivem numa pilha de execução; fault desmonta
  até a região `repair` mais interna (docs/04 §5.3) ou aborta o evento.

## Orçamento global de instruções (§6.2 do design)

TODA execução nasce com `budget` (default **1.000.000** instruções,
configurável por chamada). Cada instrução incrementa o contador global;
`contador > deadline` → Fault `Timeout`. Consequências:

- **loop infinito é impossível** — `repeat` + recursão + emissões
  recursivas tudo converge para o mesmo guardião determinístico;
- o guardião NÃO usa relógio/thread/alocação — custo por instrução é
  uma comparação de inteiros;
- fault de orçamento é reparável como qualquer outro (§5.3), MAS o
  contador é MONOTÔNICO — nunca restaura — então `repair` não vira
  máquina de loop infinito (cada captura consome orçamento de verdade).

## Determinismo (§6.3 do design) — garantias declaradas

1. Nada acessível ao script lê relógio, endereço, RNG, thread ou ordem
   de hash: natives de &BL são funções PURAS; bindings são funções do
   estado do mundo (mesma entrada ⇒ mesmo efeito);
2. floats f64 IEEE-754 e builds SEM fast-math (presets auditados —
   `-ffast-math`/`-Ofast` não existem em lugar nenhum do repo);
3. iteração de links, instâncias e emissões: ORDEM DE INSERÇÃO (vector),
   nunca unordered_map;
4. mesma cena + mesmos scripts + mesma sequência de eventos ⇒ mesmos
   efeitos — TESTADO byte-a-byte na suite (`ni determinismo`);
5. sem GC: valores são ownership direto; alocação só em concatenação de
   strings e criação de valores — nada de alocação POR instrução.

Limites (constantes, `NiValue.hpp`): budget 1M/evento, repeat ≤65.536,
links ≤64/instância, emissão ≤32 de profundidade, frames ≤256, pilha de
valores ≤65.536 slots.

## Faults e isolamento

Toda falha de runtime é `NiFault {kind, message, line, col}` — nunca
exceção (ADR-004), nunca ub. Fora de região: o EVENTO aborta e o fault
é devolvido ao host + registrado em `state.lastFault`; a instância
CONTINUA viva (o próximo evento roda). Dentro de `repair`: capturado,
registrado, execução continua (docs/04 §5.3).

Kinds: Type, NilUse, DivByZero, Range, Timeout, RepeatLimit, EmitDepth,
Stack, EntityStale, EntityNull, ComponentMissing, FieldUnknown,
BadArgument, LinkLimit, NativeError, BadWrite.

## Instâncias e o conjunto

- `NiScriptState` = programa compartilhado (`shared_ptr<const>`) +
  entidade self + globais (cópia dos zero-values) + links + lastFault;
- `NiInstanceSet` mantém a ordem de CRIAÇÃO (determinística — o host
  varre o World por inserção);
- `broadcast(evento)` dispara em TODAS as instâncias na ordem;
- `emit` propaga por BFS sobre o conjunto (§4 do design).

## Ciclo de vida integrado ao editor (ADR-044)

```
play()  → clone por serialização → NiRuntime::start():
            compila todos os NiScriptComponent do clone
            (erro de compilação = script desabilitado + log)
            cria instâncias na ordem do World
            @init de TODAS (ordem de criação)
          → fireStart(): up start de todas (mesma ordem)
tick()  → up update por instância (delta real do frame; budget por evento)
stop()  → up destroy best-effort → descarte TOTAL (bindings apontavam
          para o world do clone — morrem juntos)
```
A EDIÇÃO nunca é tocada por construção (nenhum ponteiro compartilhado
entre clone e edição — ADR-044).

## Hooks de depuração (§6.5)

`NiVm::setTraceHook(fn, stride)` — callback por instrução a cada `stride`
execuções com `{pc, linha, col, opcode, stackDepth, frameDepth}`; visão
CONST (o hook não pode mutar o VM). Desligado por padrão (custo zero).
Ver docs/08 para o estado das ferramentas.
